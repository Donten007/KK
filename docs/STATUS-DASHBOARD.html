04本轮拦下的四个真实缺陷

S1 熔断误杀合法批量工作 — 架构师自检发现
签名只含工具名时，「下载 50 个竞品页面」在窗口 K=5 内必然哈希命中→ 误熔断。批量处理 N 条、逐行处理等极常见合法工作全会被判为死循环。修正：签名须含归一化参数摘要，循环索引参数保留原值。连带：S1 从「零误判」降级为「误报极低」，F6-lite 必须加 S2 作第二道防线。Effort 1.5-2 → 1.5-2.5 人月
F6 降级方案会击穿商业模型 — PM 主动认错
「AI 生成方案 + 人工逐步确认」使 HITL率 ≤2% → 100%，直接触发 PRD 自己写的 No-Go 判据。技术降级击穿的是 567% ROI 与 ¥899 定价论证。已改为分期：F6-lite 进 MVP + F6-full 进 Phase 2。
5 个图标名会导致构建失败 — 设计师实包验证
未查 lucide.dev 文档站，而是解包比对 declare const 导出。关键坑：文档站保留已移除的旧文件，文件存在 ≠ 有导出（CircleHelp / Filter 即此类）。已立 CI 门禁 verify-icons.sh。
成本下钻的折叠入口是「看起来很专业的绕过」— 设计师自我推翻
老板看到「36 元」时想知道的是「这钱花得值不值、该砍谁」，不是 token。给他一个不需要的技术答案，比不给更糟。终裁：两层到底，不留 token 入口；需要明细的人走侧边栏自行进入。

05架构铁律

  • 越权统一 404，不返回 403。403 本身泄露「存在但无权」，构成可批量扫描的 oracle
  • RLS FORCE 不可绕过 —— 采纳 RLS 而非应用层过滤，安全是免费附赠的
  • 防时序侧信道 —— 跨租户拒绝与真实不存在的响应时间须量级一致
  • 租户上下文缺失记 WARNING —— 否则表现为「列表页空了」而非报错
  • 状态三通道（颜色+图标+文字）—— 红绿色盲下 warn/danger 模拟对比度 1.00:1 完全同色
  • checkpoint 与业务数据不同事务 —— 节点写入必须幂等，30s 心跳阈值孤儿巡检
  • 权威账务在 PostgreSQL —— 不用 Redis 计数器（AOF 每秒刷盘会丢账）
  • 接口层不序列化 token —— 不是前端隐藏，是契约层就没有该字段
